# PowPills — Next.js frontend + headless WordPress backend

A pixel-for-section rebuild of the PowPills online pharmacy homepage.

- `frontend/` — Next.js 15 (App Router, TypeScript, Tailwind CSS)
- `backend/` — WordPress with the `powpills-core` plugin (content types, seed data, REST API)
- `tools/` — copy parity check between the two sides

All product photography, promo art, avatars and the hero visual are **dummy
placeholder SVGs** in `frontend/public/images` (generated by
`frontend/scripts/generate-placeholders.py`). They are deliberately text-free so
they introduce no wording into the design.

---

## Architecture

```
WordPress (localhost:8080)                Next.js (localhost:3000)
┌───────────────────────────┐             ┌────────────────────────────┐
│ powpills_product          │             │ app/page.tsx               │
│ powpills_category         │  GET        │  └ 17 section components   │
│ powpills_promo            │ ───────────▶│                            │
│ powpills_testimonial      │  /wp-json/  │ lib/wp.ts   (fetch + merge)│
│ powpills_faq              │  powpills/  │ lib/content.ts (fallback)  │
│ option: powpills_settings │  v1/homepage│ lib/types.ts   (contract)  │
└───────────────────────────┘             └────────────────────────────┘
```

One request returns the entire homepage as a single JSON document shaped exactly
like the `HomepageContent` type in `frontend/lib/types.ts`.

If WordPress is unreachable, `lib/wp.ts` falls back to the identical static copy
in `lib/content.ts`, so the page always renders. Sections that WordPress returns
empty also fall back individually.

## Run the frontend

```bash
cd frontend
cp .env.example .env.local
npm install
npm run dev            # http://localhost:3000
```

The site renders immediately with the built-in content — WordPress is optional
for local design work.

## Run the backend

```bash
cd backend
docker compose up -d           # WordPress on http://localhost:8080
```

Then:

1. Finish the WordPress install wizard at http://localhost:8080.
2. Go to **Plugins → PowPills Core → Activate**. Activation seeds every product,
   category card, promo card, testimonial, FAQ and all global copy.
3. Visit **PowPills** in the admin sidebar to see the endpoint URL, re-seed
   content, and read newsletter signups.

Or seed from the CLI:

```bash
docker compose run --rm wpcli wp plugin activate powpills-core
docker compose run --rm wpcli wp powpills seed
docker compose run --rm wpcli wp powpills endpoint
```

Point the frontend at it with `NEXT_PUBLIC_WP_URL=http://localhost:8080` in
`frontend/.env.local`.

### REST API

| Method | Route | Purpose |
| ------ | ----- | ------- |
| `GET` | `/wp-json/powpills/v1/homepage` | Whole homepage as one document |
| `GET` | `/wp-json/powpills/v1/products?section=popular\|mens_health\|wellness` | Products for one rail |
| `POST` | `/wp-json/powpills/v1/newsletter` | `{ "email": "..." }` newsletter signup |

CORS for the storefront origin is set from the `POWPILLS_FRONTEND_ORIGIN`
constant (defined in `docker-compose.yml`, defaults to `http://localhost:3000`).

## Editing copy

Every visible string lives in exactly two mirrored places:

| Side | File |
| ---- | ---- |
| Frontend fallback | `frontend/lib/content.ts` |
| WordPress defaults | `backend/wp-content/plugins/powpills-core/includes/class-powpills-content.php` |

After editing, confirm the two are still identical:

```bash
php tools/dump-wp-copy.php && python3 tools/check-copy-parity.py
```

Expected output: `ONLY IN FRONTEND (1): ./types` (an import path, not copy) and
`ONLY IN WORDPRESS (0)`.

Once WordPress is running, editors change copy in wp-admin instead — products,
promos, testimonials and FAQs each expose a **Storefront fields** meta box, and
global copy lives in the `powpills_settings` option.

Product and testimonial images prefer a real WordPress **featured image** when
one is set, and fall back to the dummy placeholder path otherwise.

## Page structure

`frontend/app/page.tsx` renders the seventeen sections in the order they appear
in the design:

| # | Section | Component |
| - | ------- | --------- |
| 1 | Utility bar | `AnnouncementBar` |
| 2 | Logo / search / account / cart | `SiteHeader` |
| 3 | Category navigation | `MainNav` |
| 4 | Hero | `Hero` |
| 5 | Quality / price / shipping / payment / returns | `AssuranceStrip` |
| 6 | Shop by Category | `CategoryGrid` |
| 7 | Popular Products Across Our Store | `PopularProducts` |
| 8 | Three promo cards | `PromoCards` |
| 9 | Trust stats + featured review | `StatsAndReview` |
| 10 | How It Works | `HowItWorks` |
| 11 | Best Sellers in Men's Health | `ProductRow` |
| 12 | Wellness, Hair & Skin Essentials | `ProductRow` |
| 13 | Support banner | `SupportBanner` |
| 14 | What Our Customers Say | `Testimonials` |
| 15 | Frequently Asked Questions | `Faq` |
| 16 | Newsletter | `Newsletter` |
| 17 | Footer | `SiteFooter` |

Interactive behaviour: category dropdown, product tab filtering, product and
testimonial carousels, FAQ accordion, newsletter submit.

See `COPY-INVENTORY.md` for the complete string-by-string transcription.
